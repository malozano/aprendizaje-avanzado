La pregunta natural que surge al final es: ¿cómo decidir cuál usar en un problema concreto? ¿Y cómo extraer el máximo rendimiento del modelo elegido?

    Vamos a abordar esas preguntas desde tres puntos de vista complementarios:

    • Diagnóstico: Buscamos entender por qué un modelo falla y qué tipo de fallo tiene (¿demasiado simple? ¿demasiado complejo? ¿pocos datos?).
    • Regularización y selección de features: Técnicas para controlar la complejidad del modelo y eliminar información irrelevante.
    • Optimización de hiperparámetros: Métodos para buscar de forma eficiente la configuración óptima del modelo.

    Terminaremos presentando una guía práctica integrada que conecta todo lo anterior con los modelos que conocemos.

    Un principio que atraviesa todo el tema es que la selección de modelos no es una tarea que se hace al final, sino que debe planificarse desde el inicio del proyecto. Deberemos decidir cómo se particiona el dataset, qué métricas se monitorizan y cómo se toman las decisiones de diseño, todo lo cual va a determinar si las conclusiones son válidas o si están sesgadas por el proceso de selección en sí mismo.

    Compromiso sesgo-varianza y criterios de selección¶

    Descomposición sesgo-varianza¶

    Sea \(f(x)\) la función real que queremos aprender y \(\hat{f}(x)\) el estimador aprendido sobre un dataset de entrenamiento \(\mathcal{D}\) de tamaño \(N\). El error esperado de predicción sobre un nuevo punto \(x\) se puede descomponer como:

    \[\mathbb{E}_{\mathcal{D}}\left[(y - \hat{f}(x))^2\right] = \underbrace{\left(\mathbb{E}_\mathcal{D}[\hat{f}(x)] - f(x)\right)^2}_{\text{Bias}^2} + \underbrace{\mathbb{E}_\mathcal{D}\left[\left(\hat{f}(x) - \mathbb{E}_\mathcal{D}[\hat{f}(x)]\right)^2\right]}_{\text{Varianza}} + \underbrace{\sigma^2_\varepsilon}_{\text{Ruido irreducible}}\]

    Donde la esperanza se toma sobre todos los posibles datasets de entrenamiento de tamaño \(N\).

    • El sesgo (bias) mide cuánto se aleja en media la predicción del valor real. Es el error producido por las suposiciones incorrectas del modelo. Un modelo demasiado simple (baja capacidad) tiene sesgo alto, ya que no puede capturar la estructura real del problema.
    • La varianza mide cuánto varía la predicción según el dataset de entrenamiento concreto que se usa. Un modelo demasiado complejo (alta capacidad) tiene varianza alta, ya que se ajusta a los detalles del dataset de entrenamiento, incluyendo el ruido.
    • El ruido irreducible \(\sigma^2_\varepsilon\) es la varianza inherente de la variable objetivo dado \(x\), y no puede reducirse con ningún modelo, por lo que representa el suelo del error.

    El compromiso (tradeoff) consiste en que reducir el sesgo (usando modelos más complejos) tiende a aumentar la varianza, y viceversa. El objetivo es encontrar el punto de mínimo error total.

    Validación cruzada¶

    La validación cruzada (CV) es el método estándar para estimar el error de generalización de un modelo sin necesidad de un conjunto de test separado.

    K-Fold CV¶

    Se divide el dataset en \(K\) particiones (folds) de tamaño aproximadamente igual. En cada iteración \(k \in \{1, \ldots, K\}\), se entrena sobre los \(K-1\) folds restantes y se evalúa sobre el fold \(k\). La estimación del error de generalización es:

    \[\hat{\text{Err}}_{\text{CV}} = \frac{1}{K} \sum_{k=1}^K \text{Err}_k\]

    Donde \(\text{Err}_k\) es el error sobre el fold \(k\).

    Con \(K = N\) (Leave-One-Out CV, LOOCV) se obtiene un estimador menos sesgado pero con mayor varianza computacional. En la práctica, \(K = 5\) o \(K = 10\) ofrece un buen balance entre sesgo y varianza del estimador, siendo \(K = 5\) más eficiente computacionalmente y \(K = 10\) ligeramente menos sesgado.

    Problema de data leakage en CV. El pipeline completo (incluyendo normalización, selección de features, imputación de valores ausentes) debe ajustarse dentro de cada fold, usando solo los datos de entrenamiento de ese fold. Ajustar el scaler o el selector de features sobre todo el dataset antes de la CV produce estimaciones optimistas.

    # Correcto: el pipeline se ajusta dentro de cada fold
pipe = Pipeline([
    ('scaler', StandardScaler()),
    ('selector', SelectKBest(k=10)),
    ('clf', SVC())
])
scores = cross_val_score(pipe, X, y, cv=10)

    Stratified K-Fold¶

    Cuando el dataset está desbalanceado, el K-Fold estándar puede producir folds con distribuciones de clases muy distintas. El Stratified K-Fold garantiza que cada fold mantiene la misma proporción de clases que el dataset completo. Es el modo por defecto en scikit-learn para clasificación.

    CV temporal¶

    En series temporales, el K-Fold estándar viola la causalidad temporal, ya que el modelo puede "ver el futuro" durante el entrenamiento. TimeSeriesSplit garantiza que el entrenamiento siempre precede temporalmente a la evaluación. Es decir, el fold \(k\) se evalúa sobre datos más recientes que los usados para entrenar.

    Criterios de información (AIC y BIC)¶

    Los criterios de información permiten comparar modelos ajustados sobre el mismo dataset sin necesidad de un conjunto de validación separado, penalizando la complejidad del modelo (los hemos visto cuando hemos estudiado los GMM).

    AIC (Akaike Information Criterion):

    \[\text{AIC} = -2\log \hat{L} + 2p\]

    BIC (Bayesian Information Criterion):

    \[\text{BIC} = -2\log \hat{L} + p \log N\]

    Donde \(\hat{L}\) es la verosimilitud maximizada del modelo, \(p\) es el número de parámetros libres y \(N\) el tamaño del dataset. En ambos casos, menor es mejor: el término \(-2\log \hat{L}\) mide el ajuste (cuanto mejor ajuste, más pequeño) y los términos de penalización \(2p\) y \(p \log N\) penalizan la complejidad.

    La diferencia entre AIC y BIC está en la penalización: BIC penaliza más fuertemente los modelos complejos cuando \(N\) es grande (ya que \(\log N > 2\) para \(N > 7\)). En la práctica:

    • AIC tiende a seleccionar modelos más complejos y es preferible cuando el objetivo es la predicción.
    • BIC es más conservador y es preferible cuando el objetivo es la identificación del modelo verdadero (consistencia en el límite \(N \to \infty\)).

    Ambos criterios asumen que el modelo verdadero está dentro de los candidatos considerados. Cuando esto no se cumple, la validación cruzada es más robusta.

    Es importante resaltar que estos criterios necesitan que el modelo tenga una función de verosimilitud definida. Esto es algo natural en modelos probabilísticos, como por ejemplo GMM o Naive Bayes o Regresión Logística (la log-loss es directamente \(-\ln \hat{L})\), pero puede ser complicado aplicarlo a otros modelos. En modelos no probabilísticos utilizaremos normalmente CV, que es la forma de validación más utilizada en la práctica al no asumir ninguna forma funcional de la distribución de los errores.

    El problema de la comparación múltiple en selección de modelos¶

    Cuando se comparan muchos modelos mediante CV sobre el mismo dataset, el riesgo de seleccionar el mejor por azar aumenta con el número de comparaciones.

    El test de Diebold-Mariano o el test de Friedman (para múltiples modelos sobre múltiples datasets) permiten determinar si las diferencias de rendimiento son estadísticamente significativas.

    Una regla práctica conservadora es la regla 1-SE de Breiman: entre todos los modelos cuyo error CV está dentro de un error estándar del mejor, elegir el más simple. Esto favorece la parsimonia sin sacrificar rendimiento de forma estadísticamente significativa.

    El problema de la comparación múltiple en selección de modelos¶

    Cuando se usa validación cruzada (CV) para comparar modelos, se comete un error frecuente, que es tratar el valor de CV como si fuera el error de generalización real del modelo. No lo es, se trata de una estimación de ese error, y como toda estimación, tiene ruido.

    La pregunta relevante no es "¿qué modelo tiene el menor error de CV?", sino "¿tenemos evidencia suficiente de que ese modelo es realmente mejor, o estamos viendo ruido de estimación?"

    El error de CV como estimador ruidoso¶

    Dado un modelo \(h\) y un dataset \(\mathcal{D}\), el error de generalización real es:

    \[\mathcal{E}(h) = \mathbb{E}_{(x,y) \sim P}\left[L(h(x), y)\right]\]

    Lo que obtenemos con \(k\)-fold CV es una estimación de este valor:

    \[\widehat{\mathcal{E}}_{\text{CV}}(h) = \frac{1}{k}\sum_{i=1}^{k} L_i(h)\]

    Esta estimación tiene varianza propia por dos razones:

    1. Variabilidad de los folds: Cada fold es una muestra aleatoria distinta del dataset. Si hubiéramos partido los datos de otra forma, habríamos obtenido un valor numérico diferente.

    2. Correlación entre folds: Los modelos entrenados en distintos folds comparten una fracción \((1 - 1/k)\) de los datos de entrenamiento. Esto introduce dependencia entre las \(k\) estimaciones y hace que la varianza real del estimador sea mayor de lo que sugiere la fórmula naïve de la varianza de la media.

    Podemos escribir la relación entre lo observado y lo real como:

    \[\widehat{\mathcal{E}}_{\text{CV}}(h) = \mathcal{E}(h) + \varepsilon_h\]

    donde \(\varepsilon_h\) es el error de estimación, que depende tanto del modelo como de la partición aleatoria concreta que se usó.

    Ejemplo numérico¶

    Supón que se comparan dos modelos cuyos errores reales de generalización son:

    \[\mathcal{E}(h_1) = 0.2100, \quad \mathcal{E}(h_2) = 0.2120\]

    \(h_1\) es marginalmente mejor. Sin embargo, tras aplicar 10-fold CV se observa:

    \[\widehat{\mathcal{E}}_{\text{CV}}(h_1) = 0.2140, \quad \widehat{\mathcal{E}}_{\text{CV}}(h_2) = 0.2090\]

    El ruido de estimación (\(\varepsilon_{h_1} = +0.004\), \(\varepsilon_{h_2} = -0.003\)) fue suficiente para invertir el orden real de los modelos. Se selecciona \(h_2\) como ganador cuando en realidad \(h_1\) generaliza mejor. No ha habido trampa ni error metodológico, sino simplemente varianza estadística.

    Por qué el problema escala con el número de comparaciones¶

    Con un único par de modelos, el riesgo de error por ruido es limitado. El problema se agrava cuando se comparan muchos modelos simultáneamente, como ocurre en un GridSearchCV con decenas de combinaciones de hiperparámetros.

    Cada comparación tiene una probabilidad \(\alpha\) de producir un falso positivo (concluir que un modelo es mejor cuando no lo es). Al realizar \(m\) comparaciones, la probabilidad de cometer al menos un error es:

    \[P(\text{al menos un error}) = 1 - (1 - \alpha)^m\]
    Número de modelos \(m\) \(P(\text{error})\) con \(\alpha = 0.05\)
    2 10%
    10 40%
    20 64%
    50 92%
    100 99.4%

    Con 50 combinaciones de hiperparámetros (un GridSearchCV modesto), es casi seguro que el modelo "ganador" tiene una componente de suerte incorporada en su puntuación. Esto se conoce como el problema de comparaciones múltiples o, en su versión más extrema, p-hacking o data dredging.

    Nota intuitiva: con suficientes intentos, un modelo mediocre acabará obteniendo una buena puntuación de CV simplemente por azar. Cuantos más modelos se comparan, mayor es la probabilidad de que el "mejor" lo sea en parte por ruido.

    Herramientas para afrontar el problema¶

    1. Test \(t\) pareado sobre los folds (comparación de dos modelos)¶

    La aproximación más práctica cuando se comparan dos modelos sobre el mismo dataset. En lugar de comparar las medias de CV, se comprueba si la diferencia media es estadísticamente significativa.

    import numpy as np
from scipy import stats
from sklearn.model_selection import cross_val_score
from sklearn.linear_model import Ridge, Lasso

scores_A = cross_val_score(Ridge(alpha=1.0), X, y, cv=10,
                           scoring='neg_mean_squared_error')
scores_B = cross_val_score(Lasso(alpha=0.1), X, y, cv=10,
                           scoring='neg_mean_squared_error')

t_stat, p_value = stats.ttest_rel(scores_A, scores_B)

print(f"Media A: {scores_A.mean():.4f} ± {scores_A.std():.4f}")
print(f"Media B: {scores_B.mean():.4f} ± {scores_B.std():.4f}")
print(f"p-valor: {p_value:.4f}")

if p_value > 0.05:
    print("→ Sin evidencia de diferencia real. Elegir el más simple.")
else:
    print("→ Diferencia estadísticamente significativa.")

    Si \(p > 0.05\), no hay evidencia suficiente para preferir un modelo sobre el otro basándose en el rendimiento. En ese caso, el modelo más simple debe guiar la decisión.

    Limitación: El test \(t\) asume independencia entre folds, que no se cumple estrictamente en CV. Dietterich (1998) propone correcciones específicas para este caso, pero en la práctica el test \(t\) pareado es la aproximación estándar por su simplicidad.

    2. Test de Friedman + post-hoc de Nemenyi (múltiples modelos)¶

    Cuando se comparan más de dos modelos, la metodología recomendada en ML (Demšar, 2006) es el test no paramétrico de Friedman sobre rangos.

    Procedimiento:

    1. Para cada dataset (o fold), se asigna un rango a cada modelo (1 = mejor).
    2. Se calcula el rango medio \(\bar{r}_j\) de cada modelo \(j\) sobre todos los datasets.
    3. El test de Friedman contrasta \(H_0\): todos los modelos tienen el mismo rango esperado.
    4. Si se rechaza \(H_0\), se aplica el post-hoc de Nemenyi para identificar qué pares difieren significativamente.
    from scipy.stats import friedmanchisquare
import scikit_posthocs as sp
import pandas as pd

# Puntuaciones de cada modelo en múltiples datasets o repeticiones
scores = {
    'Ridge':    [0.82, 0.79, 0.85, 0.81, 0.83],
    'Lasso':    [0.80, 0.81, 0.83, 0.79, 0.82],
    'ElasticNet': [0.75, 0.77, 0.79, 0.76, 0.78],
}

stat, p = friedmanchisquare(*scores.values())
print(f"Friedman: χ²={stat:.3f}, p={p:.4f}")

if p < 0.05:
    df = pd.DataFrame(scores)
    print("\nPost-hoc de Nemenyi (p-valores por pares):")
    print(sp.posthoc_nemenyi_friedman(df))

    La regla 1-SE de Breiman¶

    Es la herramienta más directamente aplicable con sklearn y la más usada en la práctica. No requiere tests adicionales y es visualmente interpretable.

    Idea central¶

    Después de CV, cada modelo tiene un error medio y un error estándar asociado a esa estimación. El error estándar cuantifica la incertidumbre de la estimación:

    \[\text{SE}_j = \frac{\sigma_j}{\sqrt{k}}\]

    donde \(\sigma_j\) es la desviación estándar de los errores en los \(k\) folds. La regla dice:

    Entre todos los modelos cuyo error de CV cae dentro de \(\bar{e}_{\min} + \text{SE}_{\min}\), elegir el más simple.

    La lógica estadística es clara: si el error de un modelo más simple está dentro del margen de incertidumbre del mejor modelo, no tenemos evidencia para afirmar que el mejor es realmente mejor. La diferencia es estadísticamente indistinguible del ruido.

    Visualización conceptual¶

    Error CV
  │
  │         ●  ← mejor valor de CV (mínimo)
  │       ●   ●
  │─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  umbral = mín + 1·SE
  │                 ●    ●   ●  ← modelos dentro del umbral
  │                          ▲
  │                          └── elegir éste (el más simple)

    Implementación completa con sklearn¶

    import numpy as np
import matplotlib.pyplot as plt
from sklearn.linear_model import Ridge
from sklearn.model_selection import cross_val_score

# Grid de hiperparámetros (mayor alpha = mayor regularización = más simple)
alphas = np.logspace(-3, 3, 60)
mean_errors, std_errors = [], []

for alpha in alphas:
    scores = cross_val_score(Ridge(alpha=alpha), X, y,
                             cv=10, scoring='neg_mean_squared_error')
    mean_errors.append(-scores.mean())
    std_errors.append(scores.std() / np.sqrt(len(scores)))  # error estándar

mean_errors = np.array(mean_errors)
std_errors  = np.array(std_errors)

# --- Regla 1-SE ---
best_idx   = np.argmin(mean_errors)
umbral_1se = mean_errors[best_idx] + std_errors[best_idx]
within_1se = mean_errors <= umbral_1se

# El índice más a la derecha dentro del umbral = mayor alpha = más simple
chosen_idx = np.where(within_1se)[0][-1]

print(f"Alpha óptimo (mínimo CV):     {alphas[best_idx]:.4f}  "
      f"| MSE = {mean_errors[best_idx]:.4f}")
print(f"Alpha elegido (regla 1-SE):   {alphas[chosen_idx]:.4f}  "
      f"| MSE = {mean_errors[chosen_idx]:.4f}")

# --- Visualización ---
fig, ax = plt.subplots(figsize=(9, 4))
ax.semilogx(alphas, mean_errors, 'b-', lw=1.5, label='Error CV medio')
ax.fill_between(alphas,
                mean_errors - std_errors,
                mean_errors + std_errors,
                alpha=0.15, color='blue', label='±1 SE')
ax.axhline(umbral_1se, color='red', ls='--', lw=1.2,
           label=f'Umbral 1-SE = {umbral_1se:.4f}')
ax.axvline(alphas[best_idx], color='green', ls=':', lw=1.5,
           label=f'Mejor (α={alphas[best_idx]:.3f})')
ax.axvline(alphas[chosen_idx], color='red', ls='-', lw=1.5,
           label=f'Elegido 1-SE (α={alphas[chosen_idx]:.3f})')
ax.set_xlabel('alpha (regularización creciente →)')
ax.set_ylabel('MSE (CV)')
ax.set_title('Regla 1-SE de Breiman — Ridge Regression')
ax.legend(fontsize=8)
plt.tight_layout()
plt.savefig('regla_1se.svg', format='svg')
plt.show()

    Nota importante: ¿qué es "más simple"?¶

    La dirección de la complejidad depende del modelo:

    Modelo Dirección "más simple"
    Ridge / Lasso Mayor alpha (más regularización)
    Árbol de decisión Menor max_depth
    KNN Mayor n_neighbors
    SVM Mayor C → más margen (menor complejidad efectiva)
    Número de componentes (PCA, GMM) Menor n_components

    Resumen: cuándo usar cada herramienta¶

    Situación Herramienta
    Comparar 2 modelos, mismo dataset Test \(t\) pareado sobre folds de CV
    Comparar \(m > 2\) modelos en múltiples datasets Friedman + Nemenyi
    Seleccionar hiperparámetros con parsimonia Regla 1-SE
    Corrección rápida en búsqueda exhaustiva Bonferroni o Benjamini-Hochberg

    En la práctica de ML, la regla 1-SE es la opción por defecto recomendada para selección de hiperparámetros: no requiere infraestructura estadística adicional, favorece la parsimonia y produce modelos que generalizan al menos tan bien como el "ganador" nominal.

    Curvas de aprendizaje y diagnóstico de modelos¶

    Curvas de aprendizaje¶

    Las curvas de aprendizaje representan el error de entrenamiento y de validación en función del tamaño del dataset de entrenamiento \(N\). Son la herramienta más directa para diagnosticar si un modelo sufre de sesgo o varianza.

    Para generarlas, se entrena el modelo repetidamente sobre subconjuntos de tamaño \(m \in \{m_1, m_2, \ldots, N\}\) y se registra el error de entrenamiento y de validación (estimado por CV) para cada \(m\).

    Diagnóstico de alto sesgo (underfitting)¶

    Error
  |
  |-------- Error val  ─────────────
  |                                         
  |-------- Error train ────────────
  |_____________________________________ n

    Cuando el modelo tiene alto sesgo, tanto el error de entrenamiento como el de validación son altos y convergen rápidamente a un valor similar. Añadir más datos no mejora el rendimiento significativamente porque el modelo no tiene capacidad para aprender la estructura del problema.

    Diagnóstico: El modelo es demasiado simple. La solución es aumentar la capacidad del modelo (mayor profundidad en el árbol, kernel más expresivo en SVM, más features, modelo más complejo).

    Diagnóstico de alta varianza (overfitting)¶

    Error
  |
  |-------- Error val  ─────────────
  |                          ╲
  |                           ╲______
  |-------- Error train ──────────────
  |_____________________________________ n

    Cuando el modelo tiene alta varianza, el error de entrenamiento es bajo, pero el error de validación es considerablemente más alto y la brecha entre ambos no se cierra al aumentar \(N\) (o lo hace muy lentamente).

    Diagnóstico: El modelo memoriza el training set. Las soluciones son regularización, reducción de la complejidad del modelo, o más datos.

    Comportamiento ideal¶

    Error
  |
  |---- Error val  ─╲
  |                  ╲_______________
  |---- Error train ─────────────────
  |_____________________________________ n

    Ambas curvas convergen a un error bajo a medida que aumenta \(N\). La brecha es pequeña y disminuye con más datos.

    Curvas de validación¶

    Las curvas de validación representan el error de entrenamiento y validación en función de un hiperparámetro del modelo (no del tamaño del dataset). Permiten identificar la zona de underfitting y overfitting para ese hiperparámetro.

    Por ejemplo, para la profundidad máxima de un árbol de decisión:

    Error
  |
  |  Error val:   ╲              ╱
  |                ╲____________╱
  |  Error train:   ╲___________
  |__________________________________________________ profundidad
       underfitting  │  óptimo  │  overfitting

    La profundidad óptima es aquella que minimiza el error de validación. A la izquierda del mínimo el modelo tiene sesgo (demasiado simple), mientras que a la derecha tiene varianza (demasiado complejo).

    Matriz de confusión y métricas de diagnóstico¶

    Para problemas de clasificación, la matriz de confusión desglosa los errores por tipo y es imprescindible para diagnosticar el comportamiento del modelo, especialmente con clases desbalanceadas.

    Cada fila de la matriz representa las instancias de una clase real, y las columnas representan las instancias de las clases predichas.

    \[C = \begin{pmatrix} \text{TN} & \text{FP} \\ \text{FN} & \text{TP} \end{pmatrix}\]

    Las métricas derivadas más importantes:

    \[\text{Precisión} = \frac{\text{TP}}{\text{TP} + \text{FP}} \qquad \text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}} \qquad F_1 = \frac{2 \cdot \text{Prec} \cdot \text{Rec}}{\text{Prec} + \text{Rec}}\]

    El \(F_\beta\) score generaliza el F1 permitiendo ponderar diferente la precisión y el recall:

    \[F_\beta = (1 + \beta^2) \cdot \frac{\text{Prec} \cdot \text{Rec}}{\beta^2 \cdot \text{Prec} + \text{Rec}}\]

    Con \(\beta > 1\) se pondera más el recall (importante cuando los falsos negativos son más costosos que los falsos positivos, p.ej. diagnóstico de enfermedades); con \(\beta < 1\) se pondera más la precisión.

    La curva ROC representa la tasa de verdaderos positivos (recall) frente a la tasa de falsos positivos para todos los umbrales de decisión posibles. El AUC-ROC es el área bajo esa curva: 0.5 equivale a predicción aleatoria y 1.0 a clasificación perfecta. Es una métrica robusta al desbalanceo de clases porque es invariante al umbral y a la distribución de clases.

    En datasets muy desbalanceados, la curva Precision-Recall y su AUC (AP, Average Precision) son más informativas que la curva ROC, ya que esta última puede ser optimista cuando la clase negativa es muy mayoritaria.

    Regularización¶

    La regularización controla la complejidad del modelo penalizando soluciones con parámetros grandes, reduciendo la varianza a costa de introducir un sesgo controlado.

    Regularización L2 (Ridge)¶

    La regularización L2 añade a la función de pérdida un término proporcional a la norma cuadrada de los parámetros:

    \[\mathcal{L}_{\text{Ridge}}(w) = \mathcal{L}(w) + \lambda \|w\|_2^2 = \mathcal{L}(w) + \lambda \sum_{j=1}^d w_j^2\]

    El efecto es encoger todos los coeficientes hacia cero de forma proporcional, pero sin llevar ninguno exactamente a cero. La solución de Ridge para regresión lineal tiene forma cerrada:

    \[\hat{w}_{\text{Ridge}} = (X^\top X + \lambda I)^{-1} X^\top y\]

    La adición de \(\lambda I\) resuelve además el problema de invertibilidad de \(X^\top X\) cuando el número de features supera al de muestras (\(d > N\)). Ridge siempre tiene solución única independientemente de la geometría de los datos.

    Interpretación bayesiana: Ridge equivale a imponer una prior gaussiana \(w_j \sim \mathcal{N}(0, 1/2\lambda)\) sobre los pesos y tomar el estimador MAP (Maximum A Posteriori). El parámetro \(\lambda\) controla la precisión de esa prior (mayor \(\lambda\) implica creer a priori que los pesos son pequeños).

    Regularización L1 (Lasso)¶

    La regularización L1 penaliza la norma uno de los parámetros:

    \[\mathcal{L}_{\text{Lasso}}(w) = \mathcal{L}(w) + \lambda \|w\|_1 = \mathcal{L}(w) + \lambda \sum_{j=1}^d |w_j|\]

    La propiedad clave del Lasso es que produce soluciones sparse. Cuando \(\lambda\) es suficientemente grande, muchos coeficientes son exactamente cero. El Lasso realiza por tanto selección de features implícita, de forma que los coeficientes no nulos identifican las features más relevantes.

    La intuición geométrica es que las bolas de la norma L1 son hiperpirámides con vértices sobre los ejes. El mínimo del problema regularizado tiende a ocurrir en un vértice de la bola, donde exactamente un subconjunto de coordenadas es no nulo. Las bolas de la norma L2 son hiperesféricas y no tienen esa propiedad.

    No existe solución de forma cerrada para el Lasso debido a la no diferenciabilidad de \(|w_j|\) en \(w_j = 0\). Se resuelve con algoritmos como coordinate descent. En cada iteración, se optimiza \(w_j\) manteniendo todos los demás fijos, aplicando el operador de umbralización suave (soft thresholding):

    \[w_j \leftarrow S_\lambda(w_j) = \text{sign}(w_j) \max(|w_j| - \lambda, 0)\]

    Interpretación bayesiana: Lasso equivale a una prior de Laplace \(w_j \sim \text{Laplace}(0, 1/\lambda)\), que tiene colas más pesadas que la gaussiana y una mayor masa en cero, lo que favorece soluciones sparse.

    Elastic Net¶

    El Elastic Net combina las penalizaciones L1 y L2:

    \[\mathcal{L}_{\text{EN}}(w) = \mathcal{L}(w) + \lambda_1 \|w\|_1 + \lambda_2 \|w\|_2^2\]

    o equivalentemente, parametrizando con \(\lambda\) y \(\rho \in [0, 1]\):

    \[\mathcal{L}_{\text{EN}}(w) = \mathcal{L}(w) + \lambda \left[ \rho \|w\|_1 + \frac{1-\rho}{2} \|w\|_2^2 \right]\]

    El parámetro \(\rho\) controla el balance entre L1 y L2: \(\rho = 1\) recupera el Lasso, \(\rho = 0\) recupera Ridge.

    Ventaja sobre el Lasso puro: Cuando hay grupos de features altamente correlacionadas, el Lasso tiende a seleccionar arbitrariamente una de ellas y descartar el resto. El Elastic Net tiende a seleccionar o descartar features correlacionadas en grupo, lo que es más estable y generalmente más interpretable.

    Cuándo usar cada uno:

    • Ridge: cuando se espera que todas o la mayoría de las features sean relevantes, con efectos pequeños.
    • Lasso: cuando se espera que pocas features sean verdaderamente relevantes y se desea selección automática.
    • Elastic Net: cuando hay muchas features correlacionadas o cuando no se tiene certeza sobre la sparsidad de la solución real.

    Regularización en SVMs: el parámetro C¶

    En las SVMs, el parámetro \(C\) controla el tradeoff entre margen y errores de clasificación. El problema primal es:

    \[\min_{w, b, \xi} \frac{1}{2}\|w\|^2 + C \sum_{i=1}^n \xi_i \quad \text{s.a.} \quad y_i(w^\top x_i + b) \geq 1 - \xi_i, \quad \xi_i \geq 0\]

    El término \(\frac{1}{2}\|w\|^2\) es equivalente a una regularización L2 sobre \(w\). Un \(C\) pequeño equivale a una mayor penalización sobre \(\|w\|^2\) (más regularización, mayor margen, más errores permitidos), mientras que un \(C\) grande equivale a menor regularización (menor margen, menos errores en training, más riesgo de sobreajuste).

    Dropout en redes neuronales¶

    El dropout (Srivastava et al., 2014) es la técnica de regularización más usada en redes neuronales profundas. Durante el entrenamiento, en cada forward pass, cada neurona se desactiva con probabilidad \(p\) (probabilidad de dropout), y su activación se pone a cero. Las neuronas restantes se escalan por \(\frac{1}{1-p}\) para mantener el valor esperado de la activación constante.

    Formalmente, si \(h_j\) es la activación de la neurona \(j\), durante el entrenamiento:

    \[\tilde{h}_j = \frac{h_j \cdot m_j}{1-p}, \quad m_j \sim \text{Bernoulli}(1-p)\]

    Durante la inferencia, no se aplica dropout y se usan todas las neuronas con sus pesos originales (equivalente a promediar sobre todas las posibles máscaras).

    Interpretación: el dropout puede interpretarse como entrenar simultáneamente un ensemble exponencialmente grande de subredes que comparten parámetros, lo que reduce la covarianza entre neuronas y previene la co-adaptación. Existe también una conexión teórica con la regularización L2 en el caso de redes lineales.

    Valores típicos de \(p\): 0.5 para capas fully connected, 0.1-0.2 para capas convolucionales. Demasiado dropout puede aumentar el sesgo.

    4.6. Early stopping¶

    El early stopping es una forma implícita de regularización en el entrenamiento iterativo (redes neuronales, gradient boosting): se detiene el entrenamiento cuando el error de validación deja de decrecer o comienza a aumentar.

    Para gradient boosting (XGBoost, LightGBM), el número de árboles es el parámetro que controla la complejidad, y el early stopping evita construir árboles adicionales que solo reducen el error de entrenamiento. Para redes neuronales, el número de épocas juega el mismo papel.

    Se recomienda usar una paciencia (patience) de varias rondas sin mejora antes de detener el entrenamiento, para no detenerse prematuramente ante fluctuaciones del error de validación.

    5. Selección de Features¶

    La selección de features busca identificar el subconjunto de variables de entrada más relevante para el modelo, con tres motivaciones: reducir el riesgo de sobreajuste (eliminar ruido), mejorar la interpretabilidad, y reducir el coste computacional.

    Se distinguen tres familias de métodos según cómo interaccionan con el modelo.

    5.1. Métodos de filtrado (Filter methods)¶

    Los métodos de filtrado evalúan la relevancia de cada feature de forma independiente del modelo, usando medidas estadísticas univariantes. Son computacionalmente baratos pero ignoran las interacciones entre features.

    Test chi-cuadrado (\(\chi^2\)): para features categóricas y variable objetivo categórica, contrasta si la feature y la clase son independientes. Una dependencia significativa indica relevancia.

    Información mutua: mide la dependencia estadística entre la feature \(X_j\) y la variable objetivo \(Y\), capturando tanto relaciones lineales como no lineales:

    \[I(X_j; Y) = \sum_{x, y} p(x, y) \log \frac{p(x, y)}{p(x)p(y)}\]

    Un valor de \(I(X_j; Y) = 0\) indica independencia; valores altos indican alta relevancia. A diferencia de la correlación de Pearson, la información mutua detecta dependencias no lineales.

    Correlación de Pearson: para features continuas y objetivo continuo:

    \[r_{X_j, Y} = \frac{\text{Cov}(X_j, Y)}{\sigma_{X_j} \sigma_Y}\]

    Solo captura dependencias lineales. Para clasificación es menos apropiado que la información mutua.

    ANOVA F-test: para features continuas y objetivo categórico, contrasta si la media de la feature difiere entre clases. Es el test estándar en SelectKBest de scikit-learn para clasificación con features continuas.

    Limitación crítica: los métodos de filtrado evalúan cada feature en aislamiento. No detectan features que son individualmente irrelevantes pero relevantes en combinación, ni eliminan features redundantes entre sí.

    5.2. Métodos wrapper¶

    Los métodos wrapper evalúan subconjuntos de features entrenando y evaluando el modelo completo sobre cada subconjunto. Son mucho más costosos computacionalmente pero capturan las interacciones entre features y son específicos para el modelo que se va a usar.

    Eliminación recursiva de features (RFE)¶

    RFE (Recursive Feature Elimination) es el método wrapper más utilizado en la práctica:

    1. Entrenar el modelo sobre todas las features.
    2. Calcular la importancia de cada feature (coeficientes para modelos lineales, importancia de feature para árboles).
    3. Eliminar la feature menos importante.
    4. Repetir hasta llegar al número deseado de features.

    La importancia usada en el paso 2 depende del modelo: para modelos lineales se usa \(|w_j|\); para SVMs los coeficientes del hiperplano; para modelos de árbol la reducción de impureza (MDI).

    RFECV combina RFE con validación cruzada para seleccionar automáticamente el número óptimo de features: selecciona el subconjunto que maximiza la métrica de validación.

    Selección hacia adelante y hacia atrás¶

    • Forward selection: comenzar con ninguna feature y añadir en cada paso la que más mejora la métrica de validación.
    • Backward elimination: comenzar con todas las features y eliminar en cada paso la que menos degrada la métrica.
    • Stepwise: combinar ambos, añadiendo o eliminando en cada paso.

    Estos métodos son greedy y no garantizan encontrar el subconjunto óptimo, pero son eficientes cuando \(d\) no es demasiado grande.

    5.3. Métodos embedded¶

    Los métodos embedded realizan la selección de features como parte del proceso de entrenamiento del modelo. Son más eficientes que los wrapper porque no requieren reentrenar el modelo para cada subconjunto.

    Lasso: como vimos en la sección 4, la regularización L1 produce coeficientes exactamente nulos, realizando selección implícita. Las features con coeficiente no nulo son las seleccionadas.

    Importancia de features en modelos de árbol: Random Forest y Gradient Boosting calculan la importancia de cada feature como la reducción total de impureza (MDI) producida por los splits sobre esa feature, promediada sobre todos los árboles. Esta importancia puede usarse para descartar features con importancia cercana a cero.

    Advertencia sobre MDI: la importancia MDI está sesgada hacia features con muchos valores únicos (variables continuas frente a categóricas con pocas categorías). La importancia de permutación (PI) es una alternativa más fiable: mide cuánto decrece la métrica de validación al permutar aleatoriamente los valores de una feature, rompiendo su relación con la variable objetivo. Una feature irrelevante no debería causar degradación al permutarla.

    Regularización en redes neuronales: L1/L2 sobre los pesos de la primera capa actúan como selección de features en redes neuronales poco profundas.

    5.4. Multicolinealidad y el Factor de Inflación de la Varianza (VIF)¶

    Cuando dos o más features están altamente correlacionadas entre sí, los coeficientes de los modelos lineales se vuelven inestables (alta varianza). El Factor de Inflación de la Varianza cuantifica este problema:

    \[\text{VIF}_j = \frac{1}{1 - R^2_j}\]

    donde \(R^2_j\) es el coeficiente de determinación de la regresión de \(X_j\) sobre el resto de features. Un \(\text{VIF}_j > 10\) (o \(> 5\) en criterios más conservadores) indica multicolinealidad problemática para la feature \(j\). En ese caso, conviene eliminar una de las features correlacionadas o aplicar Ridge (que maneja bien la multicolinealidad por su regularización L2).

    6. Optimización de Hiperparámetros¶

    Los hiperparámetros son los parámetros del modelo que no se aprenden durante el entrenamiento sino que deben fijarse antes: la profundidad del árbol, el \(C\) de la SVM, el número de árboles del Random Forest, la tasa de aprendizaje del gradient boosting, etc. Su selección tiene un impacto enorme en el rendimiento.

    6.1. Grid Search¶

    Grid Search evalúa exhaustivamente todas las combinaciones posibles de un conjunto discreto de valores para cada hiperparámetro. Si se tienen \(k\) hiperparámetros con \(n_1, n_2, \ldots, n_k\) valores respectivamente, el número total de combinaciones es \(\prod_{i=1}^k n_i\).

    Con validación cruzada de \(K\) folds, el coste total es \(K \cdot \prod_{i=1}^k n_i\) entrenamientos del modelo. Esto crece exponencialmente con el número de hiperparámetros: para 5 hiperparámetros con 5 valores cada uno y CV de 5 folds, son \(5 \cdot 5^5 = 15625\) entrenamientos.

    Grid Search es adecuado cuando el espacio de hiperparámetros es pequeño y los hiperparámetros tienen valores razonables bien conocidos. Para espacios grandes, el coste es prohibitivo.

    6.2. Random Search¶

    Random Search (Bergstra y Bengio, 2012) muestrea aleatoriamente combinaciones de hiperparámetros de distribuciones especificadas para cada uno, en lugar de explorar una rejilla exhaustiva.

    El resultado contraintuitivo de Bergstra y Bengio es que, para un presupuesto computacional fijo (mismo número de evaluaciones), Random Search tiende a superar a Grid Search. La razón: en Grid Search, si algunos hiperparámetros son mucho más importantes que otros (lo cual es habitual), muchos puntos de la rejilla exploran las mismas configuraciones de los hiperparámetros importantes. Random Search explora una región mucho más diversa del espacio.

    Formalmente, si un hiperparámetro \(h_1\) explica el 90% de la variación del rendimiento y \(h_2\) el 10%, con 25 evaluaciones Grid Search explora solo 5 valores distintos de \(h_1\) (repitiendo los de \(h_2\)), mientras que Random Search explora 25 valores distintos de \(h_1\).

    Otra ventaja es que Random Search permite usar distribuciones continuas para los hiperparámetros (p.ej. \(\lambda \sim \text{LogUniform}(10^{-4}, 10^0)\)) en lugar de un conjunto discreto.

    6.3. Optimización Bayesiana¶

    La optimización bayesiana (BO) es el método más sofisticado y eficiente para la búsqueda de hiperparámetros. Su principio es tratar la función de rendimiento \(f(\lambda)\) (donde \(\lambda\) es el vector de hiperparámetros) como una función desconocida y costosa de evaluar, y construir un modelo probabilístico de \(f\) que se actualiza con cada evaluación para decidir inteligentemente qué configuración evaluar a continuación.

    Proceso Gaussiano como modelo sustituto¶

    El modelo sustituto más común es un Proceso Gaussiano (GP). Un GP define una distribución sobre funciones: dado un conjunto de evaluaciones previas \(\mathcal{D}_t = \{(\lambda_i, f(\lambda_i))\}_{i=1}^t\), el GP proporciona para cualquier punto nuevo \(\lambda\):

    \[f(\lambda) \mid \mathcal{D}_t \sim \mathcal{N}(\mu_t(\lambda), \sigma^2_t(\lambda))\]

    donde \(\mu_t(\lambda)\) es la predicción media (qué rendimiento espera el modelo) y \(\sigma^2_t(\lambda)\) es la incertidumbre (cuánto no sabe el modelo sobre ese punto). La función de covarianza del GP (kernel) determina la suavidad que se asume de \(f\).

    Función de adquisición¶

    La función de adquisición \(\alpha(\lambda)\) combina la media y la incertidumbre del GP para decidir qué punto evaluar a continuación, balanceando explotación (evaluar donde \(\mu_t\) es alta) y exploración (evaluar donde \(\sigma_t\) es alta).

    La función de adquisición más usada es la Expected Improvement (EI):

    \[\text{EI}(\lambda) = \mathbb{E}\left[\max(f(\lambda) - f^*, 0)\right]\]

    donde \(f^* = \max_i f(\lambda_i)\) es el mejor valor observado hasta ahora. Bajo el modelo GP, esta esperanza tiene forma analítica:

    \[\text{EI}(\lambda) = ({\mu_t(\lambda) - f^*}) \Phi(Z) + \sigma_t(\lambda) \phi(Z), \quad Z = \frac{\mu_t(\lambda) - f^*}{\sigma_t(\lambda)}\]

    donde \(\Phi\) y \(\phi\) son la CDF y PDF de la normal estándar. Puntos con \(\mu_t(\lambda) \gg f^*\) (alta explotación) o \(\sigma_t(\lambda)\) alta (alta exploración) tienen EI alto.

    El algoritmo completo¶

    1. Evaluar f en unos pocos puntos iniciales (aleatorios o por diseño).
2. Ajustar el GP sobre los puntos evaluados.
3. Maximizar la función de adquisición: λ* = argmax α(λ).
4. Evaluar f(λ*) (entrenar y validar el modelo con hiperparámetros λ*).
5. Añadir (λ*, f(λ*)) al conjunto de observaciones.
6. Volver al paso 2.

    La clave es que maximizar \(\alpha(\lambda)\) es barato (no requiere entrenar el modelo real), mientras que evaluar \(f(\lambda)\) es caro. La BO concentra las evaluaciones costosas donde tienen mayor esperanza de mejora.

    Alternativa: Tree-structured Parzen Estimator (TPE)¶

    TPE (Bergstra et al., 2011), implementado en Optuna y Hyperopt, es una alternativa a los GPs que escala mejor a espacios de alta dimensión y espacios condicionales (hiperparámetros que solo son relevantes cuando otro toma cierto valor). En lugar de modelar \(p(f|\lambda)\) directamente, modela \(p(\lambda|f > f^*)\) y \(p(\lambda|f \leq f^*)\) por separado y selecciona puntos con alto ratio entre ambas densidades.

    Herramientas: Optuna (TPE, CMA-ES, pruning de trials no prometedores), scikit-optimize (GP-based), Hyperopt, Ray Tune (escalable a clusters).

    6.4. Búsqueda de hiperparámetros con presupuesto limitado: Successive Halving y Hyperband¶

    Cuando entrenar el modelo hasta convergencia es muy caro, Successive Halving (SHA) permite identificar configuraciones prometedoras con un presupuesto total reducido:

    1. Evaluar \(n\) configuraciones aleatorias con un presupuesto mínimo \(r\) (p.ej. pocas épocas o pocos datos).
    2. Conservar la mitad con mejor rendimiento, doblar el presupuesto.
    3. Repetir hasta que queda una sola configuración.

    Hyperband (Li et al., 2017) extiende SHA combinando múltiples rondas con distintos balances entre el número de configuraciones iniciales y el presupuesto mínimo, eliminando la necesidad de especificar estos valores manualmente. Está implementado en Optuna y Ray Tune.

    7. Orientaciones Prácticas¶

    Esta sección sintetiza los criterios para elegir modelo y estrategia de optimización en función de las características del problema. No es una receta rígida — el No Free Lunch Theorem (Wolpert y Macready, 1997) establece que ningún algoritmo es superior a todos los demás en todos los problemas — pero sí una guía fundada en la experiencia acumulada de la comunidad.

    7.1. Caracterización del problema¶

    Antes de elegir un modelo, conviene responder estas preguntas:

    Pregunta Respuesta → implicación
    ¿Cuántas muestras? \(n < 1000\): modelos simples o regularizados. \(n > 100k\): deep learning viable.
    ¿Cuántas features? \(d \gg n\): regularización L1/L2 esencial. \(d\) pequeño: todos los modelos viables.
    ¿Features relevantes? Muchas irrelevantes: Lasso, RF, o selección explícita.
    ¿Features correlacionadas? Alta multicolinealidad: Ridge o Elastic Net; evitar Lasso puro.
    ¿Linealidad? Relación lineal probable: regresión logística o SVM lineal. No lineal: kernels, árboles, redes.
    ¿Interpretabilidad necesaria? Alta: regresión logística, árbol de decisión. Media: RF + SHAP. Baja: cualquier modelo.
    ¿Datos estructurados o no estructurados? Tabular: RF/GBM suelen ser la línea base. Imágenes/texto: deep learning.
    ¿Tiempo de inferencia crítico? Sí: modelos simples o árboles. Redes grandes pueden ser lentas.

    7.2. Guía por tipo de problema¶

    Clasificación binaria o multiclase, datos tabulares¶

    Punto de partida recomendado: Regresión logística regularizada (Ridge o Lasso). Es el baseline más informativo: si un modelo lineal funciona bien, no necesitas complejidad adicional, y sus coeficientes dan información interpretable sobre las features.

    Si la relación no es lineal: árbol de decisión (para interpretar la estructura) o Random Forest / Gradient Boosting (para máximo rendimiento). En la práctica, XGBoost o LightGBM son difíciles de superar en datos tabulares con ingeniería de features adecuada.

    Si las features son continuas y de escala similar y la frontera es compleja: SVM con kernel RBF. Escala peor que GBM para \(n\) grande pero es robusto con pocas muestras.

    Si la interpretabilidad es prioritaria: árbol de decisión podado o regresión logística con Lasso (selección explícita de features). Random Forest + SHAP es un buen compromiso entre potencia e interpretabilidad.

    Regresión, datos tabulares¶

    Análogo a clasificación: comenzar con Ridge como baseline lineal. Si hay no linealidad, Random Forest o Gradient Boosting para regresión. Si hay muchas features irrelevantes, Lasso o Elastic Net.

    Para series temporales, preferir modelos que respeten la causalidad temporal: validación con TimeSeriesSplit, y considerar modelos específicos (ARIMA, modelos de estado) si la estructura temporal es la principal fuente de señal.

    Datos no balanceados¶

    El desbalanceo de clases requiere atención en tres niveles: - Métrica: usar F1, AUC-ROC o Average Precision en lugar de accuracy. - Entrenamiento: class_weight='balanced' en scikit-learn ajusta los pesos de las clases inversamente proporcional a su frecuencia. - Datos: SMOTE u otras técnicas de sobremuestreo de la clase minoritaria (sección 8 del tema de aplicaciones).

    Pocos datos (\(n < 500\))¶

    Con muy pocos datos, los modelos complejos sobreajustan sistemáticamente. Preferir modelos con pocas capacidades: regresión logística con regularización fuerte, SVM lineal, o KNN con \(k\) grande. La validación cruzada con LOOCV o \(K=5\) es más apropiada que el split estándar train/test.

    El transfer learning es la técnica más efectiva cuando se dispone de un modelo preentrenado en un dominio relacionado: se usa el modelo preentrenado como extractor de features y solo se entrena una capa final sobre los pocos datos disponibles.

    7.3. Estrategia de optimización de hiperparámetros por modelo¶

    Modelo Hiperparámetros críticos Estrategia recomendada

    7.4. Un protocolo de trabajo robusto¶

    Para evitar el sesgo por selección de modelos, se recomienda el siguiente protocolo:

    1. Separar un conjunto de test al inicio y no tocarlo hasta la evaluación final. Nunca tomar decisiones de diseño basadas en el rendimiento del test.
    2. Usar validación cruzada anidada (nested CV) para una estimación insesgada del error cuando tanto la selección del modelo como la estimación del error se hacen sobre los mismos datos:
    3. CV externa: estima el error de generalización del proceso de selección completo.
    4. CV interna: selecciona los hiperparámetros óptimos para cada fold externo.
    5. Establecer un baseline trivial (predicción de la clase más frecuente, media de la variable objetivo) antes de entrenar cualquier modelo. Es sorprendente cuántas veces el modelo "sofisticado" apenas supera este baseline.
    6. Documentar todas las decisiones de diseño y sus justificaciones. Las decisiones post-hoc (ajustar el modelo después de ver los resultados de test) invalidan las conclusiones estadísticas.

    6. Robustez y Ataques Adversariales¶

    6.1. El fenómeno adversarial¶

    En 2013, Szegedy et al. descubrieron que los clasificadores de imagen basados en redes neuronales profundas son extremadamente vulnerables a perturbaciones imperceptibles al ojo humano. Una imagen correctamente clasificada puede modificarse con un ruido tan pequeño que ningún humano lo detectaría, pero la red neuronal cambia su predicción completamente — y con alta confianza.

    Este fenómeno no es exclusivo de imágenes: se ha demostrado en texto, audio, series temporales, grafos y datos tabulares. La existencia de ejemplos adversariales es una propiedad estructural de los clasificadores de alta dimensión, no un fallo de implementación.

    6.2. Taxonomía de ataques¶

    Por el conocimiento del atacante:

    • Caja blanca (white-box): el atacante conoce la arquitectura del modelo, sus pesos y puede calcular gradientes. Es el escenario más favorable para el atacante y el más usado en investigación para encontrar cotas superiores de vulnerabilidad.
    • Caja negra (black-box): el atacante solo puede hacer consultas al modelo (entrada → salida) sin acceder a su estructura interna. Más realista en la práctica.

    Por el objetivo del ataque:

    • No dirigido (untargeted): hacer que el modelo prediga cualquier clase incorrecta.
    • Dirigido (targeted): hacer que el modelo prediga una clase específica.

    Por el momento del ataque:

    • Ataques de inferencia (evasion): modificar las entradas en tiempo de prueba para engañar al modelo sin modificarlo.
    • Ataques de envenenamiento (poisoning): modificar el dataset de entrenamiento para que el modelo aprendido tenga el comportamiento deseado por el atacante.
    • Ataques de backdoor: insertar un patrón "trigger" en el dataset de entrenamiento de modo que el modelo se comporte correctamente en general pero prediga una clase específica cuando aparece el trigger.

    6.3. Ataques de evasión principales¶

    FGSM (Fast Gradient Sign Method)¶

    FGSM (Goodfellow et al., 2014) es el ataque más simple y sirvió para establecer la conexión entre la linealidad de las redes neuronales en el espacio de entrada y su vulnerabilidad adversarial. Dado un ejemplo \((x, y)\), genera un ejemplo adversarial \(x'\) con:

    \[x' = x + \varepsilon \cdot \text{sign}(\nabla_x \mathcal{L}(\theta, x, y))\]

    La perturbación \(\varepsilon \cdot \text{sign}(\nabla_x \mathcal{L})\) se añade en la dirección que maximiza la pérdida, con magnitud limitada a \(\varepsilon\) en norma \(L_\infty\). Es un ataque de un solo paso, computacionalmente barato pero no el más fuerte.

    PGD (Projected Gradient Descent)¶

    PGD (Madry et al., 2018) es la versión iterativa de FGSM. Aplica \(T\) pasos de FGSM con paso pequeño \(\alpha\), proyectando después de cada paso sobre la bola \(L_\infty\) de radio \(\varepsilon\) centrada en \(x\):

    \[x'^{(t+1)} = \Pi_{x, \varepsilon} \left( x'^{(t)} + \alpha \cdot \text{sign}(\nabla_x \mathcal{L}(\theta, x'^{(t)}, y)) \right)\]

    donde \(\Pi_{x, \varepsilon}\) es la proyección sobre el hipercubo \([x - \varepsilon, x + \varepsilon]^d\). PGD con múltiples reinicios aleatorios es considerado el ataque de caja blanca más fuerte bajo la norma \(L_\infty\).

    C&W (Carlini & Wagner)¶

    El ataque C&W (Carlini y Wagner, 2017) formula la búsqueda del ejemplo adversarial como un problema de optimización con dos objetivos: ser cercano al original y ser clasificado como la clase objetivo \(t\):

    \[\min_\delta \|\delta\|_2 + c \cdot \max(\max_{j \neq t} f(x + \delta)_j - f(x + \delta)_t, -\kappa)\]

    Es más caro computacionalmente pero produce perturbaciones mucho más pequeñas que FGSM/PGD.

    6.4. Defensa: Adversarial Training¶

    El método de defensa más efectivo conocido hasta la fecha es el entrenamiento adversarial (Madry et al., 2018): aumentar el dataset de entrenamiento con ejemplos adversariales generados durante el propio entrenamiento. El objetivo de optimización se convierte en un minimax:

    \[\min_\theta \mathbb{E}_{(x,y) \sim \mathcal{D}} \left[ \max_{\delta \in \mathcal{B}(0, \varepsilon)} \mathcal{L}(\theta, x + \delta, y) \right]\]

    El problema interno (max) se resuelve con PGD, y el problema externo (min) con SGD estándar. El coste es un mayor tiempo de entrenamiento y habitualmente una degradación de la precisión en ejemplos limpios.

    Transferibilidad: un hallazgo importante es que los ejemplos adversariales generados sobre un modelo \(A\) son frecuentemente efectivos también sobre un modelo \(B\) diferente (incluso si \(B\) tiene arquitectura distinta). Esto hace que los ataques de caja negra sean más peligrosos de lo que parecería, ya que un atacante puede entrenar un modelo sustituto sobre el que generar ejemplos adversariales.

    Herramientas: Adversarial Robustness Toolbox (IBM, soporta múltiples ataques y defensas), Foolbox, CleverHans.

    7. Deriva del Modelo y MLOps¶

    7.1. El supuesto de estacionariedad¶

    Todos los modelos de ML que hemos estudiado asumen implícitamente que la distribución de los datos es estacionaria: que los datos de producción siguen la misma distribución que los de entrenamiento. En la práctica, el mundo cambia, y los modelos que no se monitorizan ni actualizan se degradan silenciosamente.

    7.2. Taxonomía de la deriva¶

    Data drift (covariable shift): la distribución marginal de las entradas \(P(X)\) cambia, pero la relación \(P(Y|X)\) se mantiene. Ejemplo: el perfil demográfico de los usuarios de un sistema cambia con el tiempo, pero el comportamiento de cada tipo de usuario es el mismo.

    Concept drift: la relación \(P(Y|X)\) cambia. Ejemplo: el fraude bancario evoluciona y los patrones que antes eran fraudulentos ya no lo son, o nuevos patrones emergen. Es el tipo de deriva más dañino y difícil de detectar, porque el modelo puede seguir viendo inputs similares pero con una relación distinta con la salida.

    Label shift (prior probability shift): la distribución marginal de \(P(Y)\) cambia. Ejemplo: la prevalencia de una enfermedad aumenta estacionalmente.

    Concept drift repentino vs. gradual vs. recurrente: el drift puede ocurrir de forma abrupta (un cambio normativo que altera el comportamiento), gradual (evolución lenta de los hábitos), o recurrente (patrones estacionales que se repiten).

    7.3. Detección de deriva¶

    La detección de deriva en la distribución de las entradas puede abordarse estadísticamente. Para cada feature \(j\), queremos contrastar si la distribución en producción \(P_t(X_j)\) difiere de la distribución de referencia \(P_{\text{ref}}(X_j)\).

    Para variables continuas — Kolmogorov-Smirnov:

    \[D = \sup_x |F_{\text{ref}}(x) - F_t(x)|\]

    donde \(F\) denota la función de distribución acumulada empírica. El test KS contrasta \(H_0\): ambas muestras proceden de la misma distribución.

    Para variables categóricas — chi-cuadrado:

    \[\chi^2 = \sum_{k} \frac{(O_k - E_k)^2}{E_k}\]

    donde \(O_k\) son las frecuencias observadas en producción y \(E_k\) las esperadas según la distribución de referencia.

    Population Stability Index (PSI): ampliamente usado en el sector financiero, mide el cambio global en la distribución de una variable:

    \[\text{PSI} = \sum_{k=1}^{K} (p_k^t - p_k^{\text{ref}}) \cdot \ln\frac{p_k^t}{p_k^{\text{ref}}}\]

    donde \(p_k\) es la proporción de observaciones en el bin \(k\). Regla práctica: PSI < 0.1 estable, 0.1–0.25 requiere atención, > 0.25 cambio significativo.

    La detección del concept drift es más difícil porque requiere etiquetas en producción, que habitualmente llegan con retraso (o no llegan). Cuando se dispone de etiquetas, se pueden monitorizar las métricas del modelo (precisión, F1, AUC) con tests estadísticos sobre ventanas temporales deslizantes.

    7.4. Estrategias de reentrenamiento¶

    Una vez detectada la deriva, hay que decidir cómo actualizar el modelo:

    • Reentrenamiento completo: descartar el modelo actual y entrenar desde cero con datos recientes. Garantiza que el modelo refleja la distribución actual pero es costoso y puede perder patrones que sí son estables.
    • Reentrenamiento incremental (online learning): actualizar el modelo continuamente con cada nuevo dato o batch. La librería River implementa algoritmos de ML online (Hoeffding Trees, etc.) diseñados para este escenario.
    • Ventana deslizante: entrenar solo con los datos más recientes (últimos \(N\) días/meses). El tamaño de la ventana es un hiperparámetro que controla el trade-off entre adaptabilidad y estabilidad.
    • Ponderación temporal: mantener todos los datos pero asignar mayor peso a los más recientes.

    7.5. MLOps¶

    MLOps (Machine Learning Operations) es el conjunto de prácticas, herramientas y culturas organizativas que permiten desplegar y mantener sistemas de ML de forma fiable y escalable. Es la aplicación de los principios de DevOps al ciclo de vida del ML.

    Los componentes principales de una infraestructura MLOps son:

    • Tracking de experimentos: registro de hiperparámetros, métricas y artefactos de cada experimento. MLflow, Weights & Biases.
    • Versionado de datos y modelos: DVC permite versionar datasets y modelos de la misma forma que Git versiona el código.
    • Pipelines reproducibles: Kedro, ZenML.
    • Serving y despliegue: BentoML, Seldon Core, Ray Serve.
    • Monitorización en producción: Evidently AI, WhyLogs/WhyLabs.

    8. Datos Escasos y Sintéticos¶

    8.1. El problema de los datos escasos¶

    En muchos dominios críticos, los datos etiquetados son escasos o muy desbalanceados:

    • Enfermedades raras: pocos casos disponibles por definición.
    • Eventos de fraude: tasas de fraude del 0.1-1% generan datasets extremadamente desbalanceados.
    • Accidentes industriales: por suerte, son infrecuentes, pero eso hace difícil aprender a predecirlos.
    • Etiquetado caro: el etiquetado por expertos (radiólogos, juristas, lingüistas) es lento y costoso.

    8.2. Técnicas de aumentación clásica¶

    La aumentación de datos aplica transformaciones que preservan la etiqueta para generar nuevas instancias de entrenamiento a partir de las existentes.

    Para imágenes: rotaciones, traslaciones, recortes, volteos horizontales, cambios de brillo y contraste, mezclas de imágenes (Mixup, CutMix).

    Para series temporales: escalado temporal (time warping), jitter (adición de ruido), permutación de segmentos, inversión temporal.

    Para datos tabulares: el enfoque más directo es la interpolación en el espacio de features, implementada por la familia de métodos SMOTE.

    SMOTE (Synthetic Minority Over-sampling Technique)¶

    SMOTE (Chawla et al., 2002) genera instancias sintéticas de la clase minoritaria interpolando entre instancias reales. Para cada instancia \(x_i\) de la clase minoritaria:

    1. Encontrar sus \(k\) vecinos más cercanos en la clase minoritaria: \(\{x_{i_1}, \ldots, x_{i_k}\}\).
    2. Seleccionar aleatoriamente uno de ellos: \(x_{i_j}\).
    3. Generar un nuevo ejemplo: \(x_{\text{new}} = x_i + \lambda (x_{i_j} - x_i)\), donde \(\lambda \sim U(0,1)\).

    El resultado es un punto aleatorio en el segmento entre \(x_i\) y \(x_{i_j}\). Variantes como SMOTE-NC manejan variables categóricas, SMOTE-ENN combina sobremuestreo con submuestreo eliminando ejemplos ruidosos, y ADASYN pondera más los ejemplos de la clase minoritaria que son más difíciles de aprender.

    8.3. Generación de datos sintéticos¶

    Más allá de la aumentación, los modelos generativos permiten aprender la distribución de los datos y muestrear instancias completamente nuevas.

    CTGAN para datos tabulares¶

    Los datos tabulares son más difíciles de modelar que las imágenes porque mezclan variables continuas y categóricas con distribuciones arbitrarias (no gaussianas). CTGAN (Xu et al., 2019), implementado en la librería SDV, adapta las GANs a este dominio con dos innovaciones:

    • Mode-specific normalization: en lugar de normalizar las variables continuas con media y varianza, estima una mezcla de gaussianas (VGM) y normaliza cada muestra relativa al modo más probable. Esto maneja distribuciones multimodales o sesgadas.
    • Conditional generator con training-by-sampling: el generador recibe como condición el valor de una variable categórica y el entrenamiento muestrea condiciones con frecuencia inversamente proporcional a su frecuencia real, mejorando la generación de categorías raras.

    La GAN tiene la arquitectura estándar: generador \(G\) que transforma ruido \(z \sim \mathcal{N}(0, I)\) en datos sintéticos, y discriminador \(D\) que intenta distinguir datos reales de sintéticos. El objetivo es el minimax estándar:

    \[\min_G \max_D \; \mathbb{E}_{x \sim p_{\text{data}}}[\log D(x)] + \mathbb{E}_{z \sim p_z}[\log(1 - D(G(z)))]\]

    Evaluación de datos sintéticos¶

    La evaluación de la calidad de los datos sintéticos es un problema complejo que debe cubrir tres dimensiones:

    1. Fidelidad estadística: ¿se parece la distribución sintética a la real? Métricas: distancia de Jensen-Shannon entre distribuciones marginales, Wasserstein distance, diferencias en correlaciones entre variables.

    2. Utilidad: ¿sirven los datos sintéticos para entrenar modelos? El protocolo Train-on-Synthetic, Test-on-Real (TSTR) entrena un clasificador sobre datos sintéticos y lo evalúa sobre datos reales, comparando con el resultado de Train-on-Real, Test-on-Real (TRTR). Una brecha pequeña indica alta utilidad.

    3. Privacidad: los datos sintéticos pueden filtrar información sobre los datos de entrenamiento. Métricas:

    4. Membership inference attack: ¿puede un atacante determinar si un registro específico estaba en el dataset de entrenamiento? La resistencia a este ataque se mide con la métrica \(\text{DCR}\) (Distance to Closest Record): si los sintéticos son muy cercanos a los reales, se corre el riesgo de memorización.
    5. Attribute disclosure: ¿puede inferirse un atributo sensible de un individuo a partir de los datos sintéticos?

    Herramientas: SDV/CTGAN, Imbalanced-learn (SMOTE y variantes), TimeGAN (series temporales), Gretel.ai.
